## 一句话结论

工程上它是"小而美"的练家子：零依赖、防作弊设计正确、声音链路是真正亮点；
产品上它还是"好 Demo"：内容只有 3 个案件、单机无留存抓手、变现路径未验证。
现在最缺的不是新功能，而是**测试基建 + 内容量产能力 + 一个被验证的付费场景**。

## 1. 技术评审

### 1.1 做得好的地方

| 项目 | 说明 |
|---|---|
| 零依赖架构 | 后端只用 Node 内置模块（http/fetch/WebSocket），无框架无依赖，任何机器可跑（`server.js` + `public/`）。 |
| 防作弊设计 | 真相只存服务端（`solution`/`guilt`/`secret` 不下发），线索解锁是确定性关键词规则而非 LLM——可预期、可测试。 |
| 声音是核心亮点 | Sambert（可选 Key）→ Edge TTS（免费 322+ 音色）→ 浏览器兜底的三级降级；按性别/年龄/性格映射音色，比多数 AI 对话产品用心。 |
| 人物图管线 | logo（固定种子 txt2img）→ img2img 派生表情变体保住脸型；前端缺图自动回退 emoji；76 张动画风图已接入（案件卡片 + 审问肖像 + 侦探选择）。 |
| 文档纪律 | SPEC / PLAN / resources / TTS 调研 / R2 设计齐全，版本演进有据可查。 |

### 1.2 主要风险（按优先级）

1. **零自动化测试**：LLM 输出解析（`extractJson` 切片、情绪徽章解析失败回落 calm）是最脆弱的环节，却没有任何测试护住。改一个 prompt 或加一个案件就可能悄悄坏掉。→ 至少补：API 契约测试、case 数据校验测试、关键词解锁单测、judge 解析单测。
2. **案件是"编译期"数据**：`data/cases` 启动时一次性载入，改内容必须重启服务。内容迭代期建议加热重载（或 reload 端点）。
3. **git 仓库膨胀**：76 张 PNG（约 70MB+）已进 git。[R2 图片存储设计](oc_r2_image_storage_design.md) 已批准未实现——图片出 git、走对象存储是迟早要还的债（用户已开始迁移）。
4. **双语关键词解锁偏脆**：中文/英文玩家"恰好说到"关键词才解锁线索，句式一变就卡住。建议加同义词库 + 部分匹配/容错。
5. **无鉴权与限流**：本地单机没问题；一旦公网部署，`/api/chat`、`/api/accuse` 会变成免费的 DeepSeek 代理。上线前必须有白名单/限流/密钥保护。
6. **语音识别平台限制**：Web Speech API 仅 Chrome/Edge/Safari；**iOS Safari 不支持语音识别**（详见 MOBILE-APP-SPEC），Firefox 只能打字。
7. 小问题：`package.json` version 仍是 0.4.0，与文档 v0.7.2 不一致；建议发布时统一。

## 2. 商业评审

### 2.1 差异化是真实的

市面上探案游戏大多是"选择题 + 文字对话"；本作是**开口审问 + 每人独立音色 + 情绪/小动作反馈 + 二次元动画人物**，正好踩在 AI 陪伴/角色扮演热潮上，且是"有目标的推理游戏"（收集线索、指控真凶），比闲聊型 AI 伴侣更有钩子。

### 2.2 短板

- **内容太薄**：3 个案件撑不起产品。案件是 JSON 可插拔——正确解法是**案件制作流水线**（见 CASE-PIPELINE-SPEC），靠内容量取胜。
- **单机本地模式**：localStorage 存档无法跨设备，无排行榜/分享/多人；探案天然适合"同案对比推理"的社交传播（"几个问题能破案？"）。
- **变现路径不明**：本地跑、零依赖是工程美德，但对商业产品意味着无订阅、无广告、无平台分成。候选：案件包 DLC、创作者平台、企业定制（团建/教育）。
